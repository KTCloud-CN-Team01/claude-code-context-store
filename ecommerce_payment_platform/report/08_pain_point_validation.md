# 08 — 공개 발표자료 기반 페인포인트 검증 (선택)

> [04_pain_points.md](./04_pain_points.md)의 6개 페인포인트를 기술 블로그가 아닌 **공개 컨퍼런스 발표/세션 자료**로 교차검증. 블로그 글과 라이브 발표는 검증 강도가 다르므로 별도 단계로 분리.
> 주의: 컨퍼런스 발표를 찾지 못한 경우도 "근거 없음"이 아니라 **"공개 발표 문화 자체가 약하다"는 정황 증거**로 해석 가능 — 특히 PP-3, PP-4는 이 자체가 페인포인트를 강화하는 결과.

---

## PP-1. 서비스 메시 도입 ROI 판단 근거 부재 (Shopify) — ⚠️ 검증 전제 깨짐

- 핵심 근거였던 [Benchmarking Istio & Linkerd CPU](https://medium.com/@michael_87395/benchmarking-istio-linkerd-cpu-c36287e32781)(Shopify Senior Production Engineer Michael Kipper, 2019)를 WebFetch로 직접 확인한 결과 **컨퍼런스 발표 언급이 전혀 없는 순수 블로그 포스트**임이 밝혀짐. KubeCon 2019(EU/NA) 세션 목록에서도 Shopify 엔지니어의 Istio 사이드카 비용 관련 발표는 찾지 못함.
- **결론**: "Shopify가 비용을 정량화했다"는 사실 자체는 유효하지만, 이는 1차 출처가 블로그이지 라이브 발표가 아님 — 04_pain_points.md PP-1의 근거를 컨퍼런스 발표로 격상시키지는 못함. 인용 시 출처 종류(블로그)를 명확히 구분해야 함.

## PP-2. 결제 도메인 분산 트랜잭션 Unknown 상태 수작업 처리 (카카오페이) — 미확인

- if(kakao) 2022/2024/2025 세션 목록을 전수 검색했으나 분산 트랜잭션 정합성·Unknown 상태 처리를 주제로 한 카카오페이 세션은 발견되지 않음(if(kakao)2022에서 카카오페이가 8개 세션·12명 발표자로 참여한 사실은 확인되나 주제가 다름).
- **공개 발표자료 검색 결과 확인 안 됨** — 04_pain_points.md PP-2의 근거는 여전히 [tech.kakaopay.com 블로그](https://tech.kakaopay.com/post/msa-transaction/) 1건에 의존.

## PP-3. 결제 도메인은 카오스 엔지니어링 실시에 보수적 (카카오페이) — ✅ 강하게 corroborate

- if(kakao) 전체 세션 아카이브(2022/2024/2025)를 검색했으나 카카오페이·카카오 그룹 어디서도 "카오스 엔지니어링", "게임데이", "장애 주입"을 제목으로 내건 세션이 전혀 없음.
- 흥미로운 대조: if(kakao)dev2022에서 2022년 판교 데이터센터 화재의 **"재발방지대책"**은 발표됐으나([카카오 공식](https://www.kakaocorp.com/page/detail/9843)), 이는 사후 복구·이중화 체계 설명이지 사전 카오스 실험 문화가 아님.
- **결론**: 공식 개발자 컨퍼런스 차원에서도 카오스 엔지니어링 관련 발표가 전무하다는 사실 자체가, 04_pain_points.md PP-3("결제 도메인은 카오스 엔지니어링에 보수적")을 컨퍼런스 레벨에서도 재확인함.

## PP-4. 국내 기업(11번가·당근마켓) 포스트모템 공개 문화 부재 — ✅ corroborate

- DEVIEW, if(kakao), 11번가 자체 기술 블로그, 인프콘 2022, 당근 테크 밋업 등을 검색했으나 11번가·당근마켓 엔지니어가 **실제 장애를 원인-타임라인-교훈 형식으로 공개 발표**한 컨퍼런스 세션은 발견되지 않음.
- 11번가는 운영 이슈(CPU Spike, 전시 API 한계)를 블로그로는 다루지만 정식 장애 회고 발표는 없음. 당근마켓도 인프라/아키텍처 발표는 다수지만 특정 장애의 포스트모템 형식 세션은 없음.
- **공개 발표자료 검색 결과 확인 안 됨** — 04_pain_points.md PP-4("국내 기업 포스트모템 공개 문화 부재")의 컨퍼런스 레벨 재확인.

## PP-5. 11번가 하이브리드 인프라(IDC+클라우드) 과도기 기술부채 — ✅ 가장 강력한 컨퍼런스 근거 확보

- **[Spring Camp 2018 - 11번가 Spring Cloud 기반 MSA로의 전환: 지난 1년간의 이야기](https://www.slideshare.net/balladofgale/spring-camp-2018-11-spring-cloud-msa-1)**(2018-04-21, 한국 스프링 사용자 모임 KSUG 주최)에서 SK플래닛/11번가 엔지니어가 Eureka 기반 서비스 디스커버리 환경의 배포 문제·Circuit Breaker 이슈·분산 환경 모니터링 이슈를 직접 발표.
- 단, "Eurekube"라는 구체적 명칭은 이 발표에서 확인되지 않고 "Eureka" 기반 이슈로만 확인됨 — 01_company_profiles.md에서 인용한 Eurekube Operator 관련 명칭은 [별도 블로그 글](https://11st-tech.github.io/2022/07/20/eurekube-operator/)이 1차 출처이며 이 컨퍼런스 발표와는 다른 자료임을 구분해야 함.
- **결론**: 6개 페인포인트 중 유일하게 **해당 기업 소속 발표자의 실제 컨퍼런스 발표**로 직접 검증됨.

## PP-6. MSA 만능주의에 대한 반례 (Shopify·당근페이) — ⚠️ 발표 찾았으나 소속 불명확

- ["잘 키운 모노리스 하나 열 마이크로서비스 안 부럽다"](https://www.slideshare.net/arawnkr/ss-195979955)(발표자 Arawn Park, 2019 KSUG 세미나)는 모듈러 모놀리스를 명시적으로 옹호하는 발표이나, **발표자 소속이 Shopify나 당근마켓이라는 근거는 확인되지 않음**(추정 불가) — 04_pain_points.md PP-6의 직접 근거로 사용 불가.
- Shopify 관련해서는 [Between Monoliths & Microservices(RailsConf 2020)](https://www.rubyevents.org/talks/between-monoliths-microservices)에서 발표자 Vladimir Dementyev(Shopify 소속 아님, 외부 발표자)가 Shopify를 모듈러 모놀리스 사례로 **인용**한 것은 확인됨 — Shopify 자체 발표는 아니지만, 업계에서 Shopify 사례가 모듈러 모놀리스의 대표 사례로 통용된다는 정황 증거로는 사용 가능.
- 당근마켓/당근페이 자체의 "MSA 과잉분해 반대" 발표는 검색되지 않음.

| PP-2 (Unknown 상태 수작업) | 미확인 — 블로그 1건에만 의존 |

| PP-4 (국내 포스트모템 부재) | ✅ DEVIEW 등에서도 부재 확인 — 가설 강화 |

**핵심 시사점**: 6개 페인포인트 중 1개(PP-5)만 해당 기업 소속 발표자의 컨퍼런스 발표로 직접 검증되고, 2개(PP-3, PP-4)는 "발표 자체가 없다"는 사실이 역으로 페인포인트를 강화한다. 나머지 3개(PP-1, PP-2, PP-6)는 블로그 의존이거나 출처 불명확성이 있어 **04_pain_points.md 인용 시 "기술 블로그 근거"와 "컨퍼런스 발표 근거"를 구분해서 표기하는 것이 정확도를 높인다.**
