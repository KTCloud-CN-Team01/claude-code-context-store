## 2. Pain → Reliever → PP ID 매핑 (Fit 검증)

```
┌────────────────────────────┬──────────────────────────────────┬────────┐
│ Customer Pain               │ Pain Reliever                     │ PP ID  │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ 메시 도입 판단 근거 없음     │ 도입 전/후 CPU·레이턴시·에러율 측정│ PP-1   │
│ (Shopify 벤치마크: 비용정량화) │ → 대시보드(RPS/에러율/지연/mTLS)  │        │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ Unknown 상태 수기 처리       │ Saga + Resilience4j 자동 보상     │ PP-2   │
│ (카카오페이 3상태모델 반례)  │ → 자동 보상 처리율 정량 측정       │        │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ 카오스 실험 기록 안 남음     │ 설계→실시→결과공개 의무화          │ PP-3   │
│ (11번가 벤치마크: OSS기여)   │ → 1개 문서로 추적 가능             │        │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ 회고 미공유로 실수 반복      │ Blameless Postmortem 표준 문서화   │ PP-4   │
│ (당근마켓 벤치마크: 투명회고) │ → 모든 장애·실험을 케이스 스터디화 │        │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ 임시 연결 솔루션 영구화      │ 단일 오케스트레이터·클러스터 출발  │ PP-5   │
│ (11번가/카카오페이 반례)     │ → 과도기 부채 원천 차단             │        │
├────────────────────────────┼──────────────────────────────────┼────────┤
│ MSA 분리가 항상 정답인가?    │ 결제 일관성 경계 단위로 BC 최소화  │ PP-6   │
│ (Shopify/당근페이 반례)      │ → 02/04 비교 데이터로 근거 명문화  │        │
└────────────────────────────┴──────────────────────────────────┴────────┘
```
