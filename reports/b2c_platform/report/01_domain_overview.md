---

## 1. ドメイン定義

本分析における「B2C サブスクリプション & 電子決済プラットフォーム」は以下のように定義する。

```
定義:
  消費者（B2C）に対してデジタルコンテンツまたはデジタル化された
  フィジカル商品・サービスを提供し、
  電子決済（サブスクリプション課金 or 都度課金）を
  収益の中核に置くオンラインプラットフォーム。

サブドメイン（本分析では3つを横断比較）:
  ① コンテンツ配信型  — Netflix（動画）, Spotify（音楽）
  ② EC/クイックコマース型 — Amazon Prime, Coupang, Market Kurly
  ③ EdTech 型        — Inflearn
```

## 4. ドメインの技術的特性（クラウドネイティブ観点）

### 4-1. 共通技術要求

```
┌──────────────────────────────────────────────────────────────────┐
│  B2C 電子決済プラットフォームの共通技術要求                           │
├────────────────┬──────────────────────────────────────────────────┤
│ 高可用性         │ 決済障害 = 直接的な売上損失 → 99.99% 以上要求      │
│ スパイク耐性     │ セール・イベント時の 100-1000x トラフィック         │
│ 低レイテンシ     │ 決済レスポンス < 3 秒（ユーザー離脱防止）           │
│ データ整合性     │ 二重課金・未課金の防止（分散トランザクション）       │
│ グローバル配信  │ CDN・マルチリージョン展開                           │
│ セキュリティ    │ PCI DSS 準拠・個人情報保護（GDPR / 개인정보보호법）  │
└────────────────┴──────────────────────────────────────────────────┘
```

### 4-2. サブドメイン別追加要求

```
コンテンツ配信型（Netflix / Spotify）:
  + DRM（著作権保護）/ ライセンス管理
  + ABR（アダプティブビットレート）配信
  + レコメンデーションエンジン（ML 推論）

EC/クイックコマース型（Coupang / Market Kurly）:
  + リアルタイム在庫管理（分散整合性）
  + ロジスティクス最適化（配送ルーティング）
  + 商品検索・フィルタリング（全文検索エンジン）

EdTech 型（Inflearn）:
  + 動画ストリーミング + 進捗管理 DB
  + コース販売 & サブスクの混在決済
  + 講師収益分配システム
```

## 6. クラウドネイティブとの関連性マップ

```
事業課題                    →    クラウドネイティブ解決策
────────────────────────────────────────────────────────
決済障害による売上損失        →    サーキットブレーカー / Saga パターン
セール時サーバーダウン        →    水平自動スケーリング (HPA/KEDA)
デプロイ時サービス停止        →    ゼロダウンタイムデプロイ (Canary/Blue-Green)
障害検知が遅い               →    オブザーバビリティ 3 本柱（Metrics/Logs/Traces）
マイクロサービス間の障害伝播   →    Service Mesh (Istio) + mTLS
グローバル配信の品質ばらつき   →    Edge Computing + CDN 最適化
```

## 7. 市場概観まとめ

```
このドメインを選ぶクラウドネイティブ分析上の価値:

① 電子決済 = 障害が直接的な金銭損失 → 技術課題が事業インパクトと直結
② Netflix/Spotify は CN 技術の発明者（Chaos Monkey, Backstage 等）
③ Coupang は AWS 上のクラウドネイティブ運用を外部発表中
④ Market Kurly は急成長フェーズのスケール課題が豊富
⑤ Inflearn はスタートアップ的な成長課題を持ち、日本/韓国の中規模事例として適切
⑥ 3 サブドメイン横断で「決済」という共通軸が比較をシャープにする
```
